# MBA 论文写作一条龙（mba-thesis-flow）

## 定位

七阶段流水线，把"开题通过"推进到"可交付初稿"。设计原则（借鉴成熟论文 skill 的经验）：

- **资料先行**：没有模板、字数要求、数据，就不许动笔
- **逐段确认**：每阶段先回传设计，用户确认后才推进
- **门禁推进**：每阶段有检查单，通过才进下一阶段
- **事实冻结**：公司事实、数据事实先固化成底稿，正文只能基于底稿扩写
- **可核验**：文献、数字、结论三者必须可溯源

## 硬门禁（Hard Gates）

1. **资料门禁**：首次使用必须收集齐以下资料，收不齐就停在 `intake` 状态反复索要：
   - 学校格式规范 / 模板（路径或内容）
   - 总字数与分章要求
   - 开题报告或任务书（`thesis/02-开题报告.md` 存在则直接读取）
   - 往届通过答辩的样文（可选但强烈建议）
   - 数据文件（问卷原始数据 / 公司报表 / 访谈转录稿）
2. **状态机门禁**：未进入 `outline_confirmed` 状态禁止写任何正文章节。用户中途补交新模板、样文或任务书时，状态必须退回重新分析。
3. **冲突优先级**：学校模板 > 开题报告/任务书 > 用户明确要求 > 样文 > 本 skill 默认规范。冲突项必须列表向用户呈现并让用户裁决。
4. **数据真实性门禁**：分析只能基于用户提供的真实数据。**禁止编造、虚构或"合理估计"任何数据数字**；样本量、均值、系数、p 值等一切统计量必须能追溯到数据文件。无数据可用时停下来说明，不得继续。
5. **文献真实性门禁**：每条引用必须真实可核验；不确定的标 `[待核验]` 并附检索式。正文引用与文末参考文献一一对应，交付前跑对照检查。
6. **字数门禁**：按学校要求生成分章字数预算表；每写完一章统计实际字数，超出预算 10% 必须压缩后才算完成该章。
7. **去 AI 味门禁**：每章成稿后按 `references/writing-style.md` 自检，模板化句式（"随着…的快速发展""综上所述""赋能""抓手"等）必须改写。

## 执行状态机

```
intake → outline_confirmed → survey_done → design_done → analysis_done
       → writing(逐章推进) → figures → bibliography → delivery
```

- `intake`：只收资料、读样文、建事实底稿，不写正文
- 每完成一个阶段，向用户报状态并确认后推进；用户补交新材料则回退

## 七阶段流程

### 阶段 1：大纲设计 → `thesis/03-大纲.md`

- 输入：开题报告、学校模板、字数要求
- 按 `references/outline-template.md` 的五章制骨架生成建议目录 + **分章字数预算表** + 每章小节一句话说明
- 若有样文：先分析样文的章节结构、图表节奏、体量，再定大纲（学样文，不只学目录）
- **门禁**：用户明确确认目录和字数预算后，状态才进入 `outline_confirmed`

### 阶段 2：文献综述 → `thesis/04-文献综述.md`

- 按 `references/literature-review.md` 执行：三线式结构、综述矩阵表、"述 + 评"节奏、落到研究缺口
- 输入来自开题报告的文献清单 + 用户补检的文献；新文献一律先过真实性标注
- **门禁**：缺口陈述与开题报告创新点一一对应；全文无"罗列不复述"段落

### 阶段 3：研究设计 → `thesis/05-研究设计.md`

- 按 `references/research-design.md` 的方法菜单定方法（问卷实证 / 单案例 / 多案例 / 二手数据回归 / 混合 / **决策评价：AHP、DEA、熵值法、TOPSIS、灰色预测**）
- 产出：研究框架、变量与测量表（注明量表出处）、假设列表（实证类）、案例选择依据（案例类）、**指标体系分层与依据（决策评价类）**、技术路线图
- **按路径只产出对应内容（不要三套都写）**：落地诊断型写案例选择与分析框架；实证检验型写变量测量与假设；决策评价型写指标体系与模型设定。用不上的小节不写——实证题不写"指标体系分层"，评价题不写"假设列表"，案例题不写"量表信效度"。
- **类型分流**：专硕方法以"可用性优先"——够用、能答 RQ 即可，不必为严谨而过度设计；学硕方法以"严谨性优先"——效度/信度/内生性/稳健性是硬门槛，须在设计中交代。专硕可走落地诊断/实证检验/决策评价三条并列路径，学硕走实证假设检验/理论建构/系统综述等理论·实证型设计；错位时点出并纠正（注意：专硕做实证或用 DEA/AHP 评价**不是错位**）。
- **门禁**：每个假设可证伪；每项测量有出处；方法与数据类型匹配（问卷 ≥200 份才能做结构方程，n<30 不做回归改案例）

### 阶段 4：数据分析 → `thesis/06-数据分析报告.md`

- 按 `references/data-analysis.md` 执行，路径按数据类型分流：
  - 问卷数据：描述统计 → 信度（Cronbach α）→ 效度（KMO/EFA）→ 相关 → 回归 / 中介调节
  - 二手数据：描述 → 基准回归 → 稳健性 → 内生性讨论
  - 访谈/案例：编码表 → 主题归纳 → 三角验证
  - **决策评价数据**：指标归一化 → 权重计算（AHP 需报 CR、熵值法需报权重表）→ 模型求解（DEA 报效率值与规模报酬假设、TOPSIS 报相对接近度、灰色预测报级比检验与残差）→ 排序/分级 → 敏感性与稳健性检验（权重变动、方法替换）
  - **决策评价类特别提醒**：DEA 效率值与 TOPSIS 贴近度都是**相对值**，正文严禁当作绝对水平表述；DMU 数量不达标的效率结果不可用
- **门禁**：报告开头注明数据文件名与处理步骤（可复现）；所有统计量来自真实数据；结果无论显著与否如实呈现——**不显著是发现，不是失败**，禁止为显著而改数据或挑模型
- 产出物同时包含可粘贴进正文的规范表格（三线表）

### 阶段 5：论文写作 → `thesis/07-论文初稿.md`

- 逐章写作，每章节奏：回传该章小节要点 → 用户确认 → 成文 → 字数统计 → 文风自检
- 文风遵守 `references/writing-style.md`：禁空话、段落有事实锚点
- **类型分流（落点）**：专硕每章结论落到**管理启示**（谁、在什么场景、怎么用，可操作可落地）；学硕每章结论落到**理论对话/学术贡献**（与文献对话、推进了什么知识），管理启示居次、不喧宾夺主
- 章间衔接：第 4 章的分析结果必须被第 5 章结论逐条消费，不允许出现"分析里没有、结论里冒出"的建议
- **门禁**：每章通过字数门禁 + 文风门禁后才写下一章；全文完成后跑一次"引用-文献对照"预检

### 阶段 6：科研绘图 → `thesis/figures/`

- 按 `references/figures.md` 执行，必备图：技术路线图（开题已有则核对一致性）、理论模型/研究框架图、核心结果图
- 统计图优先输出绘图脚本或步骤说明（Excel 操作步骤 / Python matplotlib 代码），由用户在真实数据上出图；流程与框架类图用 Mermaid 源码交付
- **门禁**：图题、表题、编号全文连续且被正文引用；无装饰性图片

### 阶段 7：参考文献与交付 → `thesis/08-参考文献.md`、`thesis/09-交付检查单.md`

- 按 `references/references-gbt7714.md` 执行：GB/T 7714-2015 格式、去重、中英文排序按学校规范
- 生成**引用-文献对照表**：正文每一处引用 ↔ 文献表条目，双向无遗漏
- 交付检查单：摘要与关键词、目录页码、图表编号连续、字数达标、`[待核验]` 清零、查重风险自检（模板句式扫描）、致谢
- 全部通过后向用户交付，并明确提示：AI 辅助内容需按学校规定如实申报

## 与套件其他 skill 的衔接

- 入口有 `thesis/01-选题卡.md` 与 `thesis/02-开题报告.md` 时直接读取，跳过对应确认
- 前置文件不存在时，在 `intake` 阶段补问关键信息（题目、RQ、方法、数据），或建议先运行 `mba-topic-grill`、`mba-proposal-coach`

## 学术诚信边界

本 skill 辅助写作，不代写、不伪造。三条红线：

1. 不编造文献、不编造数据、不编造访谈内容
2. 分析结果如实呈现，不为显著性操纵
3. 使用范围与署名遵守用户所在学校的 AI 使用规定，交付时提醒用户申报
